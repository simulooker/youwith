# YouWith

전남대학교 전자컴퓨터공학부 YouWith 부원용 사이트입니다. 프레임워크나 패키지 설치 없이 실행합니다.

## 실행

Python이 필요합니다. 카카오 로그인 연결은 [KAKAO_SETUP.md](KAKAO_SETUP.md)를 따라 설정합니다. 운영자가 발급한 기존 아이디도 로그인 화면에서 접어둔 메뉴를 열어 사용할 수 있습니다. 기존 아이디가 필요하면 `npm run user:create -- 유저1`로 계정을 만들고 비밀번호(12자 이상)를 입력합니다. 기본 계정이나 공통 비밀번호는 없습니다. `npm run dev`를 실행한 뒤 http://127.0.0.1:4174 에서 로그인합니다.

비밀번호 변경은 `npm run user:password -- 유저1`입니다. 변경 시 기존 세션을 모두 만료시킵니다. 로그인은 12시간 유지되며 설정 → 로그아웃에서 종료합니다. 계정 DB `db/accounts.sqlite3`는 공개하거나 Git에 올리지 않습니다. 모집·지원 정보는 로그인 계정별 브라우저 저장소에 남고 다른 기기에 공유되지 않습니다. 이전의 계정 없는 저장 데이터는 삭제하지 않으며 새 계정에 자동 귀속하지 않습니다.

서버 인증을 사용하므로 HTML을 직접 열거나 GitHub Pages에 올리는 방식은 지원하지 않습니다. 외부 서비스는 Python 서버를 실행할 수 있는 호스팅과 HTTPS가 필요합니다. HTTPS 역방향 프록시 뒤에서 `python -X utf8 server/auth_server.py serve --secure-cookie`를 사용합니다. 프록시는 원래 Host를 보존하고 외부 요청을 HTTPS로만 받아야 합니다. 서버를 0.0.0.0에 바인딩할 때는 프록시에서만 접근하도록 제한합니다. 기본 실행은 이 PC에서만 접속됩니다.

`npm test`, `npm run test:server`, `npm run test:auth`로 화면 로직·수집기·인증을 검사합니다. 검사는 Node.js 기본 기능만 사용합니다.

## 설정

왼쪽 메뉴 맨 아래의 설정 아이콘 또는 **내 정보 → 설정 열기**로 이동합니다.

- 다크모드 ON/OFF
- 배경사진 표시 ON/OFF
- 화면 움직임 줄이기 ON/OFF
- 알림·권한 안내, 사용 안내, 데이터 저장 안내
- 버전 정보, 화면 설정 초기화

세 가지 화면 설정만 이 브라우저의 `youwith.preferences`에 저장됩니다. 설정 초기화는 이 값만 기본값으로 되돌립니다. 브라우저가 저장을 허용하지 않아도 현재 화면에는 설정을 적용하고 저장되지 않을 수 있음을 안내합니다. 운영체제의 동작 줄이기 설정도 존중합니다.

설정을 추가할 때는 `settings.js`의 `DEFAULT_SETTINGS`와 화면 항목을 수정하고, 필요한 스타일을 `theme.css`에 추가합니다. 인스타그램 주소는 `config.js` 한 곳에서 관리합니다. PC 메뉴에는 바로가기를 표시하고, 모바일에서는 설정 화면 안의 링크만 표시합니다. 화면별 표시 차이는 `app.js`의 `renderNavigation`과 `style.css`의 850px 이하 구역에서 관리합니다.

## 현재 기능과 저장 범위

홈은 사용자가 선택한 A(균형 잡힌 홈)로 확정했습니다. 시안 전환 버튼과 B/C 전용 코드는 제거했습니다.

공부 타이머, 일·주·월 예시 랭킹, 사각형 드래그 사과게임, 모집글 작성과 참가 신청·알림·승인 예시, 역할 찾기를 체험할 수 있습니다. 사과 합이 10인 사각형은 손을 뗄 때 제거되고, 빈 칸은 유지됩니다. 마우스와 터치 드래그만 지원하며 합계 안내와 보조 선택 버튼은 표시하지 않습니다.

부원 이름·랭킹·프로젝트 팀원 모집은 가상 데이터입니다. 공모전 탭의 기관별 공지는 실제 확인한 공개 자료입니다. 직접 작성한 모집글과 지원 정보는 이 브라우저에 저장되고, 공부·게임 기록은 새로고침하면 사라집니다. 아이디·비밀번호 로그인과 서버 세션 검증, 설정의 로그아웃을 제공합니다. 운영자가 발급한 계정만 로그인할 수 있습니다. 회원 탈퇴·휴대폰 푸시·모집 데이터의 서버 공유·PWA 설치는 아직 지원하지 않습니다.

Pretendard 글꼴은 외부 CDN을 사용하고, 연결되지 않으면 시스템 글꼴로 표시합니다. 로고는 사용자가 제공한 이미지이며 배경사진은 제공한 색상표 이미지에서 책상 배경을 재구성한 것입니다. 배경 출처와 생성 지시는 `frontend/assets/desk-background.provenance.txt`에 있습니다. `temp/preview/`는 확인용 화면 캡처이며 사이트 실행에는 필요하지 않습니다.

## 기관별 공지 확인 및 갱신

실제 공지 결과도 기관 이름을 눌러 접고 펼칠 수 있으며 검색·필터를 바꿔도 접은 상태를 유지합니다. 기관 이름의 연한 녹색은 기존 `grant-bg`/`grant-text` 밝은·어두운 테마 색상을 공유합니다. 홈 바로가기·모집 버튼의 초록/흰 선 처리는 `.home` 범위에만 적용합니다. 홈의 초 표시 형식은 `screens.js`의 `timerText()`에서 관리합니다.

기관 체크박스는 일반 수집 3곳과 공개 첫 화면 목록만 읽는 부분 지원 3곳을 제공합니다. 나머지 6곳은 원문 링크만 유지합니다. 최신 정책 점검과 이전 지원 판정의 정정 내용은 SOURCE_REVIEW.md를 참고하세요.

지원 달력은 주별로 시작일~마감일 막대를 그리고 겹치는 일정을 다른 줄에 배치합니다. 분류별 색은 `theme.css`, 막대 배치는 `notice-calendar.js`에서 관리합니다. 기관 선택은 현재 열린 페이지에서 유지하며, 새로고침하면 지원 기관 전체가 켜집니다.

메뉴 이동 효과는 `app.js`의 hashchange 처리와 `style.css`의 page-in/page-out에서 관리합니다. 화면 움직임 줄이기 설정을 켜면 이동 효과를 생략합니다. 사과게임은 144개이며 PC는 16열, 모바일은 9열로 표시합니다. 숫자는 각각 24px/22px입니다.

수집기는 `frontend/notices.json`도 함께 생성합니다. 열린 활동 화면은 `/api/notices`를 1분 간격과 화면 복귀 시 확인해 새 데이터가 있으면 반영합니다. 이 확인은 우리 사이트 파일만 읽으며 외부 기관의 수집 횟수를 늘리지 않습니다. `--cached` 옵션은 외부 요청 없이 보관 응답의 날짜 분석만 다시 검증할 때 사용합니다.

공모전 탭 바로가기: http://127.0.0.1:4174/?tab=contests#activity

`python -X utf8 server/refresh_notices.py`로 갱신합니다. `frontend/notice-data.js`가 사이트용 데이터이며 `db/notice-refresh.json`은 수집 결과와 오류 기록입니다. 기관별 5건 제한 없이, 탐색 범위에서 관련성이 확인된 공지를 모두 표시합니다. 기관별 페이지 수·검사 건수를 기록하며 RSS와 공개 목록, 같은 게시판에서 실제로 제공하는 페이지 링크를 따라 최대 20페이지를 탐색합니다. RSS 제공 범위 밖이나 페이지 링크가 공개되지 않은 과거 글까지 전부 수집했다고 주장하지 않습니다.

갱신 구조는 `기관별 RSS·공개 게시판 → 서버 수집기 → 저장된 공지 → /api/notices → 사이트`입니다. 현재 확인된 출처는 RSS와 HTML을 사용하며 아직 연결된 기관별 공식 JSON API는 없습니다. 공식 API가 제공되고 이용이 허용되는 출처는 해당 어댑터로 추가할 수 있습니다. 제한된 기관을 API/RSS로 우회하지 않습니다.

서버에서 매일 한국 시간 09:00에 실행할 systemd service/timer는 `server/deploy/`에 준비했습니다. 배포 서버에서 활성화하기 전까지 예약은 실행되지 않습니다. 수집 실행과 결과·오류 기록은 `server/notice_job.py`가 담당하며, 웹 요청은 수집을 실행하지 않고 로그인 후 저장된 최신 공지만 읽습니다. 데이터 저장 파일은 원자적으로 교체하며 API는 읽기 실패 시 기존 프런트 스냅샷을 사용합니다. 서버 배포 방법은 [SERVER_DEPLOY.md](SERVER_DEPLOY.md)를 확인하세요.

Windows 공지 예약과 Codex 자동화는 삭제했습니다. 이 PC에 새 예약을 만들지 않았습니다. PC 예약 설치 스크립트는 `temp/abandoned-local-schedule/`에 보관합니다.

전자·컴퓨터·SW·AI·반도체·통신·보안·데이터·로봇·캡스톤 등의 키워드, 기회 유형과 학과·사업단 출처를 기준으로 추립니다. 전체 학교 포털은 제목에 기술 분야가 드러나는 공지를 대상으로 합니다. 지난 연도만 명시된 공지, 결과 발표, 교직원 채용, 필수 예방교육 등은 제외합니다. 이는 규칙 기반 분류이며 개인별 지원 자격이나 관련 공지의 누락 없음을 보장하지 않습니다.

접수·모집·신청·지원·제출 기간이라고 명시된 본문 문장과 목록의 신청기간, 게시 연도가 확인되는 제목 날짜를 읽습니다. 행사·교육 운영일을 모집 마감으로 사용하지 않습니다. 연도 불명, 복수 일정, 제목·본문 불일치, 이미지·첨부파일 안의 날짜는 추측하지 않고 **기간 확인 필요**로 분류합니다. 달력은 확정된 모집 기간만 표시하고 시작일이 없으면 마감일에만 표시합니다. 마감은 날짜 기준이며 당일의 정확한 시각·조기 마감·지원 자격은 원문을 확인해야 합니다.

올콘은 공식 약관에서 사전 승낙 없는 복제·유통 제한을 확인하여 `db/notice-sources.json`의 `collection: link-only`로 자동 수집을 보류했습니다. 기관 선택과 원문 바로가기는 유지합니다. 다른 기관도 RSS 제공이나 robots.txt 허용이 재이용 허락을 뜻하는 것은 아니므로 운영 전 이용조건을 확인해야 합니다. robots.txt가 제한하거나 확인되지 않으면 해당 접근은 중단하고, 로그인·CAPTCHA·접근 차단을 우회하지 않습니다. 서버별 요청 간격은 최소 1.2초 또는 명시된 crawl-delay이며, 동일 응답은 30분간 캐시합니다. 글 본문 전체·포스터·첨부파일은 사이트에 재게시하지 않습니다.

최초 검사 근거는 `temp/research/notice-source-check.json`, 원본 응답은 `temp/research/notice-pages/`에 보관합니다. 최초 검사 명령 `python server/check_notice_sources.py`는 과거 방식의 점검 보고서만 생성하며 현재 화면 데이터를 덮어쓰지 않습니다. 새 수집기의 임시 응답은 `db/notice-cache/`에 있고 `frontend/` 밖에 두어 사이트에서 제공하지 않습니다.

Windows에서는 Python의 인증서 저장소에서 체인을 검증하지 못하는 일부 사이트에 한해 기본 `curl.exe`로 재확인합니다. 인증서 검증을 끄지 않습니다. 다른 운영 환경에서는 해당 환경에서의 접속을 재검증해야 합니다.

공지 파서 검사: `python -m unittest discover -s tests -p "test_notice*.py"` / 달력·데이터 검사: `node --test`

공지 기관과 유형은 접을 수 있는 필터이며 유형 색은 달력과 같습니다. 필터 아래에서 목록/달력을 전환합니다. PC는 달력 오른쪽, 모바일은 달력 아래에 선택 날짜의 일정을 보여줍니다. 메뉴 순서를 따라 위로 이동하면 왼쪽에서, 아래로 이동하면 오른쪽에서 다음 화면이 등장합니다. 홈의 새로운 도전 카드와 내 정보의 앱 설정·푸시 알림 행은 삭제했습니다.

공지 기관/유형은 흰 영역 안에 가로로 배치된 회색 버튼입니다. 클릭한 버튼의 선택 창만 아래로 펼칩니다. 유형 선택 항목은 배경색 없이 표시하며 달력의 분류 색만 유지합니다.

## 프로젝트 폴더 구조

```text
frontend/       화면, 스타일, 이미지, 브라우저용 공지 데이터
server/         공지 수집과 분석 Python 코드
db/             수집 대상 설정, 활성 응답 캐시, 최신 수집 결과
tests/          화면 로직과 공지 파서 검사
temp/           과거 화면 캡처, 최초 조사 자료, 옛 캐시와 수정 전 파일
.impeccable/    현재 디자인 설정과 화면 지침
```

아직 DBMS나 회원 API 서버는 없습니다. db는 현재 사용하는 JSON 설정·데이터·캐시 폴더이고, server는 공지 수집 코드입니다. 프론트엔드에서 읽는 notice-data.js와 notices.json은 frontend에 유지합니다. 개발 서버는 frontend만 제공하므로 db와 temp는 웹에 노출되지 않습니다.

`npm run test:server`로 Python 검사를, `npm run notices:refresh`로 공지를 갱신합니다. 최초 접속 검사 `python -X utf8 server/check_notice_sources.py`의 새 결과는 db/audit에 저장됩니다. temp/research는 이동 전 조사 근거를 그대로 보관한 자료입니다. temp/reorganization-manifest.json에는 이동 경로와 이동 당시 파일 해시가 있습니다. 수정한 텍스트 파일의 원본은 temp/before-reorganization에 .before 확장자로 보관합니다.

이 프로젝트의 작업 배분은 AGENTS.md의 mcp-model-router 지침을 따릅니다. Codex가 설계·핵심 구현·수정·검증·최종 통합을 책임집니다.


최근 화면 수정: 홈 모집글은 중립 배경의 행과 초록 아이콘·제목으로 표시합니다. 사과게임은 제목 왼쪽·남은 시간 가운데·점수 오른쪽이며 점수는 테두리 없는 기본 글자색, PC 32px/휴대폰 28px입니다. 공부 그래프에는 요일별 시간:분을 표시하고 예시 기록을 구분합니다. 설정은 한 열로 모으고 화면 설정 3개의 설명을 제거했습니다. 소개는 학술동아리로 표시하며 공지 소개 패널은 제거하고 필터 이름을 게시글 유형으로 변경했습니다.

팀 모집의 내가 만든 프로젝트 영역에서 글을 다시 열고 지원자 이름·전공·기술·소개·지원 상태를 확인할 수 있습니다. `youwith.recruitment.v1`에 이 브라우저의 모집글과 지원 정보를 저장합니다. 프로젝트는 인덱스가 아닌 고유 ID로 연결합니다. 초기 글·부원 정보는 예시이며 실제 부원 간 공유, 안전한 작성자 권한, 휴대폰 푸시는 회원 인증과 서버 연결이 필요합니다. 로컬 소유자 표시는 보안 권한 검증을 대체하지 않습니다. 저장 불가 시 현재 화면에서는 사용하되 새로고침 후 유지되지 않음을 알립니다. 화면 설정 초기화는 모집·지원 정보를 지우지 않습니다.

현재 분류 규칙·전공별 추천 설계·RSS와 재이용 조건·12개 기관 상태 및 해결 방법은 [공지 운영 안내](NOTICE_GUIDE.md)를 참고하세요. 전공별 추천은 설계 제안이며 이번 수정에서 새 추천 필터를 구현한 것은 아닙니다.

최근 추가: 내 모집글은 상세에서 수정·삭제할 수 있으며 삭제 시 연결된 지원 정보도 정리합니다. 수정은 프로젝트 ID와 기존 지원 정보를 유지합니다. 공모전에는 게시글 유형 오른쪽의 전공 선택 버튼을 추가했고 컴퓨터·전자·반도체를 제목 키워드로 OR 필터링합니다. 유형·기관·검색과는 AND로 적용하고, 전공을 고르지 않으면 전체입니다. 올콘 공식 검색 링크와 [제휴 문의 초안](ALLCON_PERMISSION_REQUEST.md)을 추가했습니다. [12곳 이용조건 재점검](SOURCE_REVIEW.md)과 db/source-policy-review.json에서 최신 출처 상태를 확인하세요.

카카오 로그인은 최초 접수 → 운영진 승인 → 재로그인 순서입니다. `npm run members:list`, `npm run members:approve -- 회원ID`, `npm run members:revoke -- 회원ID`로 관리합니다. 승인 취소는 기존 세션도 즉시 폐기합니다. 키·시크릿 파일 `db/auth-settings.json`은 Git에 올리지 않습니다.


## 기타 공식 API 연결

공지 기관 필터는 전남대(학교·학부·공대·성장마루·공학교육혁신센터·취업진로포털·교육혁신본부), 사업단(차세대통신·AICOSS·반도체특성화·소프트웨어중심), 그 외(올콘·K-Startup·중소벤처기업부·과기정통부)로 나눕니다. 세 API는 각각 체크박스로 켜고 끄며, 각 공지의 게시글 유형·전공·기간 필터를 함께 적용합니다. 저장된 API 묶음은 화면에서 출처별로 나눠 보여주며 기존 중복 제거를 공유합니다. 원래 12개 기관과 별도의 추가 출처이며, 공식 API가 제공한 내용만 처리하고 연결된 웹페이지·포스터·첨부파일은 수집하지 않습니다.

서버 전용 `db/notice-api-settings.json`의 `DATA_GO_KR_SERVICE_KEY` 한 곳에 공공데이터포털의 공통 인증키를 입력하면 세 API가 함께 사용합니다. 이 파일은 Git 제외 대상입니다. 환경변수로도 같은 이름을 지정할 수 있습니다. 기관별 키가 다를 때만 `KSTARTUP_SERVICE_KEY`, `MSS_SERVICE_KEY`, `MSIT_SERVICE_KEY`를 따로 지정하면 해당 기관에서 공통키보다 우선합니다. 같은 항목은 환경변수가 파일보다 우선하며 빈 기관별 키는 공통키를 사용합니다. 키는 프런트엔드·채팅·GitHub에 넣지 않습니다.

신청할 API는 [K-Startup 15125364](https://www.data.go.kr/data/15125364/openapi.do), [중소벤처기업부 15113297](https://www.data.go.kr/data/15113297/openapi.do), [과기정통부 15074634](https://www.data.go.kr/data/15074634/openapi.do)입니다. 일반 인증키의 Decoding 값을 권장하며, Encoding 값을 입력해도 한 번 해제한 뒤 요청에 맞게 인코딩합니다. 각 서비스의 활용신청·승인·쿼터를 확인해야 합니다. 키 입력만으로 수집 결과가 자동 변경되지는 않습니다. 입력 후 `npm run notices:refresh:apis`를 실행하면 세 API만 갱신하며 기존 12개 기관은 다시 요청하지 않습니다. `npm run notices:refresh`는 기존 기관도 함께 갱신합니다. 서버 배포 후에는 기존 매일 09시 서버 작업에서 같은 수집기가 실행됩니다. 이 PC에는 수집 예약을 설치하지 않습니다.

공식 명세에 따른 필드: K-Startup은 `pbanc_rcpt_bgng_dt`/`pbanc_rcpt_end_dt`, 중소벤처기업부는 `applicationStartDate`/`applicationEndDate`를 사용합니다. API 본문에 명시된 신청기간도 검사하며, 등록일·행사일을 모집기간으로 바꾸지 않습니다. 기간이 없으면 `기간 확인 필요`로 목록에 표시하고 달력에서는 제외합니다. 기본 모집 상태는 전체(마감 제외)이며, 확인된 마감 공지는 숨깁니다.

같은 공지는 선택된 기관 안에서 원문 주소(추적 파라미터 제외), 또는 충분히 구체적인 동일 제목과 동일 마감일을 비교해 목록·달력에 한 번만 표시합니다. 시작일·마감일이 다른 차수는 합치지 않습니다. 제목이 크게 달라지거나 기간·원문 주소가 모두 다른 재게시물까지 의미적으로 동일하다고 보장하지 않습니다.

수집은 기관당 최대 200페이지, 50건 단위이며 탐색 상한 여부를 결과에 기록합니다. 일부 API 실패 시 해당 API의 기존 미마감 공지를 유지하며 오류에 인증키를 남기지 않습니다. 키가 없으면 외부 API를 호출하지 않고 연결 대기로 표시합니다. 키 없는 모의 응답 테스트는 실제 계정의 API 승인·호출 성공 검증을 대신하지 않습니다.


## Blog

Tech·성과공유는 승인된 부원이 읽고 댓글을 남길 수 있으며, 글 작성·수정·삭제는 관리자만 가능합니다. 문의사항은 승인된 부원이 질문을 작성하고 본인 글·댓글을 수정·삭제하며, 관리자는 전체 글·댓글을 관리합니다. 검색·태그·12개 단위 목록과 기본 Markdown(소제목·강조·목록·코드·HTTP(S) 링크)을 지원합니다. 파일당 최대 10MB 첨부를 지원합니다. 첨부파일은 승인된 부원만 다운로드하며 글 수정 권한이 있는 사람만 추가·삭제합니다. HTML은 실행하지 않고 문자로 표시합니다.

Blog 글·댓글은 `db/accounts.sqlite3`에 저장되며 부원·기기 간 공유됩니다. 서버 데이터 폴더를 영구 저장소로 연결하고 SQLite 파일을 백업해야 합니다. 모집 데이터의 브라우저 저장 방식과는 별개입니다.

기존에 발급된 로컬 `admin` 계정은 최초 권한 마이그레이션 때 관리자로 지정됩니다. 신규 계정은 이름과 관계없이 일반 부원이며, 카카오 신규 회원은 승인 후 이용합니다. `npm run members:list`로 내부 회원 ID와 권한을 확인하고 다음 명령으로 관리자를 지정하거나 해제합니다. 변경은 기존 로그인에도 즉시 적용됩니다.

```
python -X utf8 server/auth_server.py grant-admin 내부회원ID
python -X utf8 server/auth_server.py revoke-admin 내부회원ID
```

공모전 모집 목록의 **기관별로**는 기존 기관별 접이식 목록을 유지합니다. **유형별로**는 선택한 게시글 유형·기관·전공·검색 조건을 유지하면서 기관 구분 없이 게시일 최신순으로 모읍니다. 게시일이 없는 글은 마지막에 표시하고 모집 시작일·마감일로 대체하지 않습니다. 원문 목록의 별도 날짜 칸, RSS 게시일 및 공식 API 게시일 필드를 사용합니다. 목록 보기 전환은 선택 표시 이동과 짧은 등장 효과를 사용하며 OS와 사이트의 동작 줄이기 설정을 모두 존중합니다.

전공 필터는 컴퓨터정보통신공학전공·전자공학전공·시스템반도체공학전공의 정식 명칭을 사용합니다. 정보통신·네트워크·무선통신, 회로·제어·신호처리, 칩설계·반도체 공정 등 키워드를 확장했고 공통 키워드는 여러 전공에 함께 추천합니다. 복수 선택해도 같은 공지는 한 번만 표시합니다. 올콘 공식 검색 안내는 제거했습니다. 올콘 외 출처는 자동 수집을 시도하되 robots 제한·로그인·방화벽을 우회하지 않습니다.


놀이터의 테트리스는 `frontend/tetris.js`에서 관리합니다. 7종 블록, 줄 제거·점수·레벨, 다음 블록, 키보드 및 휴대폰 버튼, 화면 이탈 시 일시정지를 지원합니다. 플레이 기록은 현재 페이지 세션에만 유지하며 서버 랭킹은 없습니다. 홈의 식사 메뉴 추천은 예정 카드만 표시합니다.

Blog 첨부파일은 `blog_attachments` 테이블의 바이너리 데이터로 저장되므로 별도 파일 폴더가 필요하지 않습니다. `db/accounts.sqlite3` 백업에 첨부도 포함됩니다. 실제 파일 크기는 서버에서 10×1024×1024바이트 이하로 검사하고, HTML 등도 실행하지 않고 다운로드로 제공합니다. 부분 실패 시 글과 성공한 첨부를 보존하고 남은 파일을 재시도합니다. 동일 글·이름·내용의 중복 업로드를 합쳐 연결 실패 후 중복 저장을 방지합니다. 첨부는 암호화 파일 보관소나 악성코드 검사 기능을 제공하는 것은 아닙니다.


## Tech HTML 콘텐츠

Tech 목록은 PC 3열·태블릿 2열·휴대폰 1열 정사각형 카드입니다. MOSFET은 `frontend/tech/mosfet.html`이 진입점이며 같은 폴더의 CSS/JS로 화면과 3D 모델을 관리합니다. `frontend/blog.js`의 `TECH_ARTICLES`에 제목·소개·경로를 추가하면 새로운 HTML 콘텐츠를 목록에 연결할 수 있습니다. 기존 DB Tech 글도 카드로 유지되며 작성·수정·삭제 권한은 그대로입니다. HTML은 개발자가 관리하는 파일만 실행하며 Blog 첨부 HTML을 자동 실행하지 않습니다.

3D 엔진은 `frontend/vendor/three`에 포함한 Three.js 0.187.0(MIT)입니다. 외부 CDN 호출 없이 실행합니다. `mosfet-cover.png`는 사용자가 제공한 카드 hover/focus 배경이며 CSS의 48% 어두운 덮개를 적용합니다. 3D 페이지는 바닥·벽·천장이 이어지는 정지 격자 공간을 사용합니다. 별·성운은 제거했습니다. NMOS는 학습용 단순화 단면 모델로 실제 비율이나 전기적 시뮬레이션을 뜻하지 않습니다. Gate ON/OFF에 따른 상대 이동 전하 농도·전자/정공 이동과 부위별 분해·확대를 지원합니다. 수치 전기 해석이나 실제 공정 모델은 아닙니다. 3D에는 WebGL2 지원이 필요하며 실패 시 안내 문구를 표시합니다.

MOSFET은 PC에서 왼쪽 3D 격자 공간과 오른쪽 모델 설정 패널로 나눕니다. 휴대폰에서는 패널이 모델 아래에 놓입니다. 전자 움직임 보기 버튼은 준비 중인 비활성 항목이며 실제 전자 시뮬레이션은 아직 없습니다.


## GitHub Pages 공개 보기

현재 GitHub Pages는 로그인 없이 화면을 둘러볼 수 있습니다. `.github/workflows/static.yml`이 배포본 `frontend/deployment.js`의 공개 보기 설정을 켭니다. 로컬 원본은 false이며 Python 서버의 로그인·운영진 승인·Blog API 권한은 유지합니다. 공개 보기에서는 관리자 권한을 부여하지 않으며 계정·서버 DB·인증키를 제공하지 않습니다.

공개 보기에서 홈·게임·공부 타이머·기존 공지·Tech HTML 콘텐츠를 볼 수 있습니다. 공지는 배포 당시 저장본이며 서버 예약 수집이 실행되는 것은 아닙니다. 모집 데이터는 방문자의 브라우저에만 저장되고 다른 사용자와 공유되지 않습니다. DB를 쓰는 Blog 글·댓글·첨부파일 등록은 비활성화하고 준비 중으로 표시합니다. 로그인 기능을 다시 적용하려면 실제 Python 서버를 배포하고 Pages 공개 보기 설정을 사용하지 않습니다.


## Tech 반도체·AI 실험실

새 콘텐츠: `frontend/tech/finfet.html`, `gaafet.html`, `cfet.html`, `neural-network.html`, `decision-tree.html`. 카메라·격자·조명·접근성 조작은 `lab-viewer.js`, 반도체 구조는 `semiconductor.js`에서 관리합니다. MOSFET도 같은 공유 소자 코드로 관리합니다. `mosfet.js`는 공유 코드의 진입 연결입니다. 카드와 hover 배경은 사용자가 제공한 주제별 `*-cover.png`를 함께 사용합니다.

신경망 계산은 `neural-math.js`의 2–4–1 tanh/sigmoid 네트워크입니다. XOR 네 표본 전체의 BCE 손실을 평균내어 경사하강법으로 학습합니다. 예측 흐름은 선택 표본 하나를, 학습은 네 표본 전체를 보여줍니다. 결정트리는 `decision-tree-math.js`의 작은 CART 분류기로 가상 과일 표본 10개를 지니 불순도 기준으로 분할합니다. 두 모델은 경우 1·경우 2를 골라 이전/다음 단계와 결과 바로 보기로 탐색합니다. 학습은 개발 중에 한 번 계산하고 `learning-scenarios.js`에 저장하며 브라우저에서는 저장된 기록과 3D 장면만 표시합니다. 수치를 바꿀 때는 `npm run tech:build-scenarios`로 다시 생성합니다. 계산 구현과 재현 검사는 유지합니다. 실제 데이터 모델이나 반도체 전기 시뮬레이터는 아닙니다.


### 소자 동작·분해 및 저장 학습 기록

- `frontend/tech/semiconductor.js`: 네 소자의 구조, 수직 분해/재조립, 부위 선택과 카메라 확대, 입자 표시를 관리합니다. 이동 입자는 채널별 공유 점 객체를 사용하며 페이지가 숨겨지면 그리기를 멈춥니다. 동작 줄이기 설정에서는 고정 분포로 표시합니다.
- `frontend/tech/device-state.js`: Gate 논리 상태와 부위별 역할·도핑 설명입니다. P/N 도핑은 고정이고, 이동 전하 농도만 Gate에 따라 달라집니다. CFET의 nFET과 pFET은 상보 동작하며 pFET의 주 운반자는 정공입니다. 상대 농도, 형상, 누설 생략은 학습용 가정입니다.
- `scripts/build-learning-scenarios.mjs`: 원래 수학 모델로 0/1/200/4,000회 XOR 학습과 깊이 0/1/2 CART를 계산합니다. 생성된 `frontend/tech/learning-scenarios.js`는 약 14 KB이며 런타임 학습 코드와 분리합니다.
- `frontend/tech/scenario-controls.js`: 두 모델이 공유하는 경우 선택·단계 이동입니다. `guided-labs.css`는 해당 화면의 배치만 관리합니다.
- `tests/guided-learning.test.cjs`: 저장 결과를 원래 계산과 대조하고, 상보 Gate 상태와 런타임 학습 코드 미사용을 검사합니다.

원리 자료: [MIT CMOS 강의](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c3/c3s1/), [imec CFET 설명](https://www.imec-int.com/en/press/imec-demonstrates-functional-monolithic-cfet-devices-stacked-bottom-and-top-contacts). 입력 전압은 두 상태로 단순화하며, 공핍 폭·실제 전류나 Poisson/수송 방정식을 계산하는 TCAD 모델이 아닙니다.


### 3D 화면과 오른쪽 설명 목차

여섯 Tech 페이지는 화면 전체에 하나의 WebGL 격자 공간을 그립니다. 별도의 아래 설명 영역은 없으며, 조작·구조 설명·학습 원리·결과 표를 오른쪽 반투명 패널의 목차에 배치합니다. 페이지 전체 대신 패널 안에서만 스크롤합니다. 휴대폰에서는 같은 3D 위로 오른쪽 설명창을 열고 닫으며, 닫힌 창은 키보드·화면 읽기 탐색에서 제외합니다.

`frontend/tech/immersive-layout.css`는 전체 화면·블러·목차 배치를, `lab-interface.js`는 모바일 열기/닫기·Escape·3D 부위 선택 시 설명 열기를 관리합니다. `lab-viewer.js`는 오른쪽 설명창의 폭만큼 투영 중심을 왼쪽으로 옮겨 모델을 가리지 않으면서 배경은 패널 뒤까지 그립니다. 새 내용도 페이지 아래 대신 해당 패널의 목차에 추가합니다.
